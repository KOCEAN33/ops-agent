# Candidates

Deferred work: each item names what triggers it.

- **Build order**: after the first deployment, the stopgap tools with their RBAC and admission policy. The stopgap tools bring the Write record in `docs/design/shape.md`, with tests that a rerun after a completed autonomous stop stops nothing new and that an approval from an ended turn authorizes nothing. Each step passes the `coding-review` pass that `CLAUDE.md` requires.
- **Old hand-off shape**: `IssueQueue` converts a hand-off queued as `{input, answer, queries}` before the three-section issue. Once the cluster runs the new image and no such row is pending, delete the conversion.
- **Compaction within a turn**: compaction covers the session's stored history, not the steps of the running turn. If a turn's own tool output passes the turn cap, mask its older results between steps too.
- **Issue link in Discord**: the thread does not name its issue. If the owner looks the issue up by hand, post its URL in the thread once it opens.
- **Minimum share measurement**: the 20% minimum share in Autonomous targets in `docs/design/chosen.md` is unmeasured. Before autonomous stops are turned on, have approval-path turns compute and report each candidate's share without stopping, and set the value from what real pressure shows.
- **Prompt caching**: worth adding once tool loops resend long histories within a turn. The spend math already prices cache reads and 5-minute cache writes.
- **Org-level pricing modifiers**: `cost()` assumes list prices. An organization default of `inference_geo: "us"` (1.1x) or a 1-hour cache TTL would make it underbill. Check the owner's Anthropic organization settings before deployment.
- **Other providers**: add OpenRouter and OrcaRouter when their keys exist, each with its own price source for the spend middleware.
- **Outbox log volume**: during a Discord outage the outbox logs a failed post on every 2-second poll. When logs ship to Loki and an outage floods them, log once per outage instead.
- **Posts dropped on a revoked permission**: every 4xx drops a post, so a 403 after the bot loses a permission drops each post until the owner fixes it. If posts are lost this way, keep 403 posts queued like an outage.
- **Crash attempts on healthy turns**: a crash counts an attempt on every turn running at the time, so three crashes caused by one turn can end a healthy turn beside it at the attempt limit. Raise it with the owner if that happens.
- **Thinking-only messages in stored history**: a turn stored before the empty-answer retry can end with an assistant message that holds one reasoning part with empty text and a signature. History replays it into the session's later turns, and whether Anthropic accepts it there is unchecked. If a later turn on such a session fails with a 400 that names that message, drop reasoning-only assistant messages when history loads.
- **DNS failures on issue writes**: issue writes have failed with `getaddrinfo EAI_AGAIN api.github.com` and with timeouts. `IssueQueue` keeps such a write queued and retries it, so no hand-off is lost. If the failures recur or delay hand-offs by minutes, check the pod's DNS path: the NetworkPolicy's egress to the cluster DNS and the DNS pods' health.
- **Owner moves an issue's repository**: the session's first write fixes its issue's repository, so an owner reply naming another repository changes nothing, and only a manual transfer moves the issue. The model picks by where the fix lands, which can differ from where the cause sits. If the owner transfers issues by hand often, let a thread reply from the owner's ID move the issue to a listed repository.
